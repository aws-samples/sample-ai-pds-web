AI-PDS (AI-Driven Product Discovery and Strategy) is a capabilities-first framework that helps
non-technical business leaders — PMs, VPs of Product, CTOs exploring adjacencies — discover, prioritize,
and prototype AI use cases before committing engineering resources. AI orchestrates every phase from
customer discovery to market launch. Humans retain decision authority at each gate.

This repo provides the **web** implementation: the AI-PLC Discovery workflow as a conversation in the
browser, with nothing to install on the participants' machines. For the other implementations, see
[Supported implementations](#supported-implementations).

### What it does

| Capability | What happens | You get |
|---|---|---|
| Envision | Pain point analysis + PR/FAQ (Working Backwards) | PR/FAQ document |
| Use Case Intake | Document & categorize N use cases | Use Case Repository |
| Prioritize | Dual scoring (Agentic vs Application) | Ranked Backlog |
| Prototype | Generate specs, then build and host the prototype and its validation survey | `PROTOTYPE-*.md` files, a running prototype, survey results |
| Product Strategy | Positioning, business model, KPIs | Strategy Document |
| Go-to-Market | Segmentation, sales motions, launch | GTM Plan |

**Three entry points:** Start from pain points, use cases, or existing prototype specs.
**Every stage is an exit point:** Stop whenever you have what you need.

### How the web implementation works

A Claude Agent SDK agent drives the Discovery methodology, and the frontend renders its turns live
over SSE. The prototype spec Discovery produces is built and hosted as a real app from the same
screen, and continues into a validation survey shared through an unauthenticated link. What Discovery
settled then leaves as a handoff package for AI-DLC — a vision document and the decisions behind it.
The UI and the generated artifacts both support Korean and English, and administrators manage users,
the model catalog and the brand design profile from the same app.

```
frontend/          Next.js 15 (App Router) — dashboard · workspace · document review · prototypes · survey · handoff · admin · manual
backend/           FastAPI — Discovery agent · SSE relay · S3 persistence · prototype build/hosting · survey · handoff package · JWT verification
infra/             CDK (TypeScript) — six stacks, Seoul by default
steering-files/    the AI-PLC ruleset — a submodule of aws-samples/sample-ai-plc, carried unmodified
discovery-config/  CLAUDE_CONFIG_DIR for the Discovery agent
proto-config/      CLAUDE_CONFIG_DIR for the build agent — must differ from the one above
```

## The AI-PLC ruleset

The Discovery workflow is the AI-PLC ruleset from
[aws-samples/sample-ai-plc](https://github.com/aws-samples/sample-ai-plc), the Agentic IDE
implementation of AI-PDS — the same workflow the other implementations run. This web implementation
adds what a chat transcript cannot: a browser UI, live turns, document review, and building and hosting
the prototype and its survey from the same screen.

The ruleset is **not copied here.** It is the `steering-files/` submodule, pinned to an upstream commit
and used unmodified — a copy drifts, and the canonical source is upstream. Clone with it:

```bash
git clone --recurse-submodules https://github.com/aws-samples/sample-ai-pds-web.git
git submodule update --init --recursive      # if you already cloned without it
```

An empty `steering-files/` raises no error; the agent just stops following the methodology. The backend
copies the ruleset into the agent's workspace on every turn, so moving the submodule pointer
(`git submodule update --remote steering-files`, commit, push, `sudo aipds-update`) takes effect on the
next turn. Changes to the workflow itself belong upstream.

## Deploying

A single `cdk deploy --all` brings up an app you can sign in to: the EC2 instance clones this repo, builds
and starts the backend and frontend, and CloudFront goes in front of it.

**Prerequisites:** Node.js 20+, administrator-level AWS credentials (it creates IAM roles, Cognito and a
VPC), and an account that can call Claude on Bedrock. For the last one, submit the **Anthropic
first-time-use form** once for the account (or the organization's management account) and have a
Marketplace payment method. Without them, the deployment succeeds and the first conversation fails with
`AccessDeniedException`.

```bash
cd infra
npm ci
npx cdk bootstrap aws://<ACCOUNT_ID>/ap-northeast-2        # once per account/region
npx cdk deploy --all --require-approval never \
  --parameters AipdsAuthStack:SeedPassword='<temporary-password>'
```

- **It takes 15–20 minutes**, and CloudFront may answer 502 for a few minutes after `cdk deploy` returns
  while the instance finishes its first build. Nothing needs to be run by hand.
- **What gets deployed is pushed `main`.** The instance clones `origin/main` at boot, and `cdk deploy`
  never updates code — that is `sudo aipds-update`.
- **Open** the `AipdsHostingStack.DistributionDomain` output and **sign in** as `admin@aipds.local` or
  `pm@aipds.local` with the `SeedPassword` value. It is a temporary password (valid 30 days) that each
  user replaces at first login. It must satisfy the pool policy — 8+ characters with an uppercase
  letter, a lowercase letter, a digit and a symbol — or CloudFormation rejects it before the deployment
  starts.
- **MFA is off.** Sign-in is a password alone, which is enough for a workshop sample but not for real
  customer material: a leaked admin password hands over user and role management too. Before using it
  beyond a workshop, require MFA in `infra/lib/aipds-auth-stack.ts` (`mfa: cognito.Mfa.REQUIRED` with
  `mfaSecondFactor: { otp: true, sms: false }` — an authenticator app).
- **Other settings chosen for a workshop, not for production.** Each line carries a warning comment
  with the setting to change:
  - Cognito has no threat protection (compromised-credential detection, risk-based sign-in) — that needs
    the Plus feature plan (`aipds-auth-stack.ts`).
  - `cdk destroy` deletes the user pool and the artifacts bucket with everything in it, and the bucket
    has no versioning or access logs (`aipds-auth-stack.ts`, `aipds-drill-stack.ts`).

Another region, the stack outputs, updating the code, the sandbox, teardown and troubleshooting are in
**`/manual` → Install, operate, troubleshoot**. What each stack creates, why the CloudFront → instance leg
is private HTTP, and the regions that need `AIPDS_AVAILABILITY_ZONES` are in
[`infra/README.md`](infra/README.md).

## Responsible AI

AI-PDS Web drafts product documents, prototypes and survey syntheses with Claude models on Amazon
Bedrock. Everything it produces is a draft for a person to judge, and the tool is built around that.

- **People decide.** A stage closes only when a person answers its question sheet or approves the
  Discovery document at the approval gate. Options marked *★ AI pick* are suggestions, not defaults. In
  the handoff package, a row the model adds to the open-questions table must quote its source and code
  checks the quote is there, and AI suggestions stay marked until someone confirms them.
- **What the AI did is visible.** The app — not the AI — writes everything a user types and every answer
  submitted to `audit.md` verbatim with the real time. Each turn's tool calls and changed files, the AI's
  own verification summary, and what each set of answers changed in the documents are shown on screen.
- **Evidence and assumptions are kept apart.** Documents must state material unknowns and never present
  an assumption as customer evidence. Survey syntheses report each respondent persona separately and do
  not count respondents outside the target users as validating a hypothesis. A survey is still a small,
  self-selected sample, so check the synthesis against the CSV of individual responses.

**Limits to plan for.**

- Model output can be wrong, incomplete or invented. Verify figures, market facts and quotes before
  they leave the workshop.
- Prototypes are throwaway code for validating an idea, not production software, and they are shared
  through links that open without an account. Do not put real personal or confidential data into a
  prototype or a survey.
- Uploaded material is sent to the model. Upload only what the workshop needs; values that look like
  credentials are redacted from the audit record, but nothing else is filtered.
- Amazon Bedrock Guardrails are not configured. Add them if your use requires content filtering —
  for example, a prototype that calls Bedrock itself can pass a guardrail with its Converse calls.
- The deployed roles invoke Claude through **global** cross-Region inference profiles, which can
  process a request in any supported commercial AWS Region; data at rest stays in your account and
  Region. If you have data residency requirements, use a geographic profile and narrow the Bedrock
  permissions in `infra/lib/backend-permissions.ts` to match.

See the [AWS Responsible AI Policy](https://aws.amazon.com/ai/responsible-ai/policy/).
